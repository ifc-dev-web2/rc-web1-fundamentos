# Projeto Semestre — Portal Escolar

## Apresentação

Neste trabalho final, cada estudante deverá planejar, desenvolver e publicar um
**portal relacionado ao ambiente escolar**, utilizando os conhecimentos de
**HTML, CSS e JavaScript** trabalhados durante a disciplina.

O projeto será desenvolvido em **duas versões evolutivas**. Na primeira versão,
o foco estará na estrutura, no conteúdo e no visual do portal, utilizando HTML e
CSS. Na segunda versão, o mesmo projeto será ampliado com recursos de interação
desenvolvidos em JavaScript.

O portal deverá atender a uma necessidade real ou imaginária da comunidade
escolar. Algumas possibilidades são:

- portal de notícias da escola;
- portal de eventos e atividades;
- portal de divulgação de cursos;
- portal de projetos desenvolvidos pelos estudantes;
- portal de esportes ou atividades culturais;
- portal de oportunidades, estágios e bolsas;
- guia para novos estudantes;
- portal de serviços e informações escolares;
- outro tema relacionado à escola, mediante aprovação do professor.

> [!IMPORTANT]
> O projeto deverá ser estruturado como um **portal com diferentes páginas e
> seções**, e não como uma landing page ou uma página única de apresentação.

## Objetivos

O trabalho tem como objetivo aplicar, de forma integrada, os seguintes
conteúdos:

- estruturação de páginas com HTML;
- utilização de HTML semântico;
- estilização e organização visual com CSS;
- construção de layouts com Flexbox;
- responsividade;
- manipulação do HTML com JavaScript;
- eventos, funções e interações;
- organização dos arquivos do projeto;
- navegação entre diferentes páginas;
- versionamento com Git e GitHub;
- publicação de uma aplicação web.

## Modalidade

O trabalho será desenvolvido de maneira **individual**.

Cada estudante será responsável por todo o processo de planejamento,
desenvolvimento, organização, publicação e apresentação do seu portal.

## Etapas de desenvolvimento

### Versão 1 — Estrutura e interface do portal

Na primeira entrega, o portal deverá ser desenvolvido somente com **HTML e
CSS**.

Esta versão deverá contemplar:

- definição e documentação do tema;
- identificação do público-alvo;
- mapa de páginas do portal;
- wireframe ou protótipo;
- no mínimo cinco páginas HTML;
- HTML semântico;
- identidade visual consistente;
- layouts construídos com Flexbox;
- responsividade para diferentes tamanhos de tela;
- navegação funcional entre todas as páginas;
- conteúdo contextualizado;
- publicação da primeira versão.

> [!NOTE]
> A Versão 1 não deverá possuir funcionalidades implementadas com JavaScript.
> Entretanto, o estudante já deverá planejar e documentar as interações que
> pretende desenvolver na Versão 2.

### Versão 2 — Interatividade com JavaScript

Na segunda entrega, o estudante deverá continuar trabalhando no **mesmo
portal**, preservando e aprimorando o que foi desenvolvido na Versão 1.

Nesta etapa, serão adicionadas as funcionalidades com JavaScript. O estudante
também poderá corrigir problemas de conteúdo, navegação, responsividade ou
organização identificados na primeira entrega.

## Planejamento do projeto

Antes de iniciar o desenvolvimento, o estudante deverá definir:

1. o nome do portal;
2. o tema escolhido;
3. o público-alvo;
4. o problema ou a necessidade que o portal pretende atender;
5. as informações que serão apresentadas;
6. as páginas que farão parte do projeto;
7. a identidade visual;
8. as funcionalidades que serão desenvolvidas com JavaScript na Versão 2.

A proposta deverá estar relacionada ao contexto escolar, mas não precisa
representar oficialmente o Instituto Federal Catarinense.

## Quantidade mínima de páginas

O portal deverá possuir **no mínimo cinco páginas HTML diferentes**.

Uma possível organização é:

1. **Página inicial:** apresentação e principais destaques do portal;
2. **Notícias ou novidades:** listagem de publicações;
3. **Eventos ou atividades:** divulgação de eventos escolares;
4. **Cursos, projetos ou serviços:** informações específicas sobre o tema;
5. **Sobre ou contato:** apresentação do portal, autoria e formulário de
   contato.

As páginas poderão ser modificadas conforme o tema escolhido, desde que o
portal mantenha a quantidade mínima solicitada e apresente uma organização
coerente.

Todas as páginas deverão estar conectadas por um menu de navegação funcional.

## Requisitos de HTML

O projeto deverá apresentar:

- no mínimo cinco páginas HTML;
- títulos e subtítulos organizados corretamente;
- cabeçalho;
- menu de navegação;
- conteúdo principal;
- seções organizadas;
- rodapé;
- imagens com texto alternativo;
- links internos entre as páginas;
- pelo menos uma lista;
- pelo menos um formulário;
- uso adequado de elementos semânticos, como `header`, `nav`, `main`,
  `section`, `article`, `aside` e `footer`.

Não será suficiente utilizar apenas elementos `div` para estruturar todas as
partes do portal.

## Requisitos de CSS

O portal deverá possuir uma identidade visual consistente entre todas as
páginas. O CSS deverá contemplar:

- arquivo CSS externo;
- padronização de cores;
- padronização de tipografia;
- espaçamentos adequados;
- estilização do cabeçalho, menu e rodapé;
- utilização de Flexbox em pelo menos duas partes do layout;
- cards ou componentes para organizar informações;
- imagens responsivas;
- efeitos de interação, como `:hover` e `:focus`;
- adaptação para diferentes tamanhos de tela;
- pelo menos uma media query.

O conteúdo não poderá apresentar elementos sobrepostos, textos cortados ou
rolagem horizontal indevida.

## Planejamento do JavaScript na Versão 1

Embora a primeira versão não utilize JavaScript, o estudante deverá incluir no
`README.md` uma seção chamada **Funcionalidades planejadas para a Versão 2**.

Para cada funcionalidade planejada, deverá informar:

- nome da funcionalidade;
- página em que será utilizada;
- elementos da página envolvidos;
- ação realizada pelo usuário;
- comportamento esperado;
- importância da funcionalidade para o portal.

Exemplo:

| Funcionalidade | Página | Ação do usuário | Comportamento esperado |
| --- | --- | --- | --- |
| Filtro de notícias | `noticias.html` | Selecionar uma categoria | Exibir somente as notícias da categoria escolhida |
| Validação de contato | `contato.html` | Enviar o formulário | Verificar os campos e apresentar mensagens de orientação |
| Menu para celular | Todas | Tocar no botão do menu | Exibir ou ocultar os links de navegação |

Esse planejamento poderá ser revisado durante o desenvolvimento, desde que as
alterações sejam atualizadas no `README.md`.

## Requisitos de JavaScript da Versão 2

Na segunda versão, o portal deverá possuir **no mínimo três funcionalidades
desenvolvidas com JavaScript**.

Exemplos de funcionalidades:

- menu responsivo;
- filtro de notícias, eventos ou projetos;
- campo de pesquisa;
- validação de formulário;
- contador de caracteres;
- alternância entre tema claro e escuro;
- exibição e ocultação de informações;
- galeria de imagens;
- carrossel;
- modal com detalhes;
- atualização dinâmica de conteúdo;
- armazenamento de uma preferência com `localStorage`.

As funcionalidades deverão possuir uma finalidade dentro do portal. Não será
suficiente adicionar um botão ou um `alert()` sem relação com a proposta do
projeto.

O JavaScript deverá estar em arquivo externo e utilizar:

- seleção de elementos do HTML;
- eventos;
- funções;
- condições ou validações;
- manipulação de conteúdo, atributos ou classes dos elementos.

## Conteúdo do portal

O portal deverá apresentar conteúdo suficiente para demonstrar sua organização.
Cada página deverá possuir:

- título;
- conteúdo relacionado ao tema;
- elementos visuais;
- navegação funcional;
- identificação clara da seção acessada.

Não serão aceitas páginas praticamente vazias, criadas apenas para atingir a
quantidade mínima solicitada.

Os textos poderão ser fictícios, mas deverão estar contextualizados e bem
apresentados. Evite utilizar grandes blocos de `Lorem ipsum`.

## Responsividade

O portal deverá funcionar adequadamente em computadores, tablets e celulares.

O estudante deverá verificar se:

- o menu continua utilizável;
- os textos permanecem legíveis;
- as imagens não ultrapassam o espaço disponível;
- os cards são reorganizados em telas menores;
- não existe rolagem horizontal indevida;
- botões e links possuem tamanho adequado para interação.

## Organização dos arquivos

O projeto deverá possuir uma estrutura organizada. Exemplo:

```text
nome-do-projeto/
├── index.html
├── noticias.html
├── eventos.html
├── projetos.html
├── contato.html
├── assets/
│   ├── css/
│   │   └── global.css
│   ├── js/
│   │   └── script.js
│   └── images/
├── README.md
└── LICENSE
```

Os nomes dos arquivos deverão ser escritos com letras minúsculas, sem espaços,
sem acentos e de maneira clara e descritiva.

## Documentação no README

O arquivo `README.md` do projeto deverá apresentar:

- nome do projeto;
- descrição do portal;
- problema ou necessidade identificada;
- público-alvo;
- nome completo do estudante;
- páginas desenvolvidas;
- funcionalidades implementadas com JavaScript;
- tecnologias utilizadas;
- instruções para executar o projeto;
- link da aplicação publicada;
- imagens ou capturas de tela do resultado;
- referências utilizadas.

Na Versão 1, o `README.md` também deverá possuir a seção **Funcionalidades
planejadas para a Versão 2**, conforme as orientações deste enunciado.

## Entregas

### Entrega da Versão 1

A primeira entrega deverá conter:

- link do repositório no GitHub;
- código-fonte das páginas HTML e dos arquivos CSS;
- arquivo `README.md` atualizado;
- mapa das páginas do portal;
- wireframe ou protótipo;
- documentação das funcionalidades planejadas para a Versão 2;
- link da primeira versão publicada.

### Entrega da Versão 2

A segunda entrega deverá conter:

- o mesmo repositório utilizado na Versão 1;
- correções ou melhorias realizadas na estrutura e no visual;
- arquivos JavaScript organizados;
- no mínimo três funcionalidades implementadas;
- arquivo `README.md` atualizado com as funcionalidades concluídas;
- link da versão final publicada;
- apresentação individual do projeto.

O portal poderá ser publicado por meio do **GitHub Pages**. Todos os links
deverão ser testados antes de cada entrega.

## Apresentação individual

Durante a apresentação, o estudante deverá:

1. explicar o tema escolhido;
2. apresentar o problema ou necessidade identificada;
3. informar o público-alvo;
4. explicar como o conteúdo foi organizado;
5. demonstrar as páginas desenvolvidas;
6. demonstrar as funcionalidades criadas com JavaScript;
7. comentar as dificuldades encontradas;
8. apresentar a aplicação publicada;
9. responder às perguntas do professor sobre o código.

## Restrições

O projeto deverá ser desenvolvido principalmente com:

- HTML;
- CSS;
- JavaScript.

Não será permitido utilizar templates prontos que entreguem a interface
completa. Também não será permitido copiar integralmente outro site ou projeto
encontrado na internet.

Referências visuais poderão ser utilizadas, mas o planejamento e a
implementação deverão ser realizados pelo próprio estudante. Códigos, imagens,
ícones ou conteúdos externos utilizados deverão ser referenciados no
`README.md`.

## Uso de Inteligência Artificial

Ferramentas de Inteligência Artificial poderão ser utilizadas como apoio para:

- compreender mensagens de erro;
- revisar textos;
- pesquisar conceitos;
- esclarecer dúvidas;
- receber sugestões de melhoria.

Entretanto, o estudante deverá compreender todo o código entregue. Durante a
apresentação, o professor poderá solicitar:

- explicação de partes do código;
- alteração de uma funcionalidade;
- identificação de um elemento HTML ou de uma regra CSS;
- explicação do funcionamento do JavaScript.

Caso o estudante não consiga explicar ou modificar o próprio projeto, isso
poderá afetar sua avaliação individual.
