# Trabalho Individual — Portal de Tema Livre

## Apresentação

Neste trabalho, cada estudante deverá planejar, desenvolver e publicar um
**portal de tema livre**, utilizando os conhecimentos de HTML, CSS e JavaScript
trabalhados durante a disciplina.

O estudante poderá escolher um assunto de seu interesse, como tecnologia,
cinema, música, jogos, esportes, culinária, turismo, literatura, animais,
ciência, cultura, sustentabilidade ou outro tema relevante.

O projeto será desenvolvido concomitantemente ao portal escolar em dupla, mas
este trabalho deverá ser realizado de maneira **integralmente individual**.

> [!IMPORTANT]
> O projeto deverá funcionar como um portal com diferentes páginas e seções.
> Não será aceita uma landing page ou uma página única de apresentação.

## Modalidade e autoria

O trabalho será desenvolvido individualmente. Cada estudante será responsável
por:

- definir o tema e o público-alvo;
- planejar a organização do portal;
- elaborar o wireframe;
- desenvolver o HTML e o CSS;
- planejar e implementar as interações com JavaScript;
- organizar o repositório;
- publicar e apresentar o projeto.

O tema, a identidade visual, os textos, a estrutura e o código não poderão ser
uma cópia do portal escolar desenvolvido em dupla. Conhecimentos poderão ser
aproveitados, mas os dois projetos deverão possuir propostas e soluções
próprias.

## Objetivos

O trabalho tem como objetivos:

- verificar individualmente a aprendizagem dos conteúdos da disciplina;
- desenvolver autonomia no planejamento de uma aplicação web;
- aplicar HTML semântico;
- criar layouts com CSS e Flexbox;
- desenvolver interfaces responsivas;
- planejar interações adequadas ao contexto do portal;
- implementar comportamentos com JavaScript;
- organizar, versionar e publicar um projeto completo.

## Desenvolvimento em duas versões

### Versão 1 — HTML e CSS

Na primeira versão, o estudante deverá desenvolver a estrutura, o conteúdo e a
interface visual do portal utilizando somente **HTML e CSS**.

A Versão 1 deverá possuir:

- definição e justificativa do tema;
- identificação do público-alvo;
- mapa de páginas;
- wireframe ou protótipo;
- no mínimo três páginas HTML;
- navegação funcional entre as páginas;
- HTML semântico;
- identidade visual consistente;
- layouts construídos com Flexbox;
- conteúdo contextualizado;
- responsividade;
- publicação no GitHub Pages;
- documentação das funcionalidades planejadas para a Versão 2.

> [!NOTE]
> A Versão 1 não deverá possuir funcionalidades implementadas com JavaScript.
> Nesta etapa, as futuras interações deverão apenas ser planejadas e registradas
> no `README.md`.

### Versão 2 — JavaScript

Na segunda versão, o estudante deverá continuar trabalhando no mesmo portal e
adicionar as funcionalidades planejadas com JavaScript.

Também será possível corrigir ou aprimorar problemas encontrados na primeira
versão, como navegação, responsividade, organização visual, conteúdo ou
acessibilidade.

## Escolha e aprovação do tema

O tema é livre, mas deverá possibilitar a criação de um portal com conteúdo
suficiente para, no mínimo, três páginas diferentes.

Antes de iniciar o desenvolvimento, o estudante deverá apresentar:

1. nome provisório do portal;
2. tema escolhido;
3. objetivo do projeto;
4. público-alvo;
5. relação das páginas que serão criadas;
6. breve descrição do conteúdo de cada página;
7. ideias iniciais de interações com JavaScript.

O tema deverá ser aprovado pelo professor.

## Quantidade mínima de páginas

O portal deverá possuir **no mínimo três páginas HTML diferentes**.

Uma possível organização é:

1. **Página inicial:** apresentação do portal e principais destaques;
2. **Página de conteúdo:** notícias, artigos, produtos, obras, destinos, receitas
   ou outro conteúdo relacionado ao tema;
3. **Sobre ou contato:** apresentação do projeto, autoria e formulário.

O estudante poderá criar outras páginas conforme a necessidade do projeto.

Todas as páginas deverão possuir navegação funcional e manter a mesma identidade
visual.

## Requisitos de HTML

O projeto deverá apresentar:

- no mínimo três páginas HTML;
- estrutura básica correta em todos os documentos;
- títulos e subtítulos organizados de maneira hierárquica;
- cabeçalho;
- menu de navegação;
- conteúdo principal;
- seções e artigos;
- rodapé;
- imagens com texto alternativo;
- links entre as páginas;
- pelo menos uma lista;
- pelo menos um formulário;
- uso adequado de elementos como `header`, `nav`, `main`, `section`, `article`,
  `aside` e `footer`.

Não será suficiente utilizar apenas elementos `div` para estruturar o portal.

## Requisitos de CSS

O portal deverá possuir uma identidade visual consistente. O CSS deverá
contemplar:

- arquivo CSS externo;
- definição de cores e tipografia;
- espaçamentos adequados;
- estilização do cabeçalho, menu e rodapé;
- uso de Flexbox em pelo menos duas partes do portal;
- cards ou componentes para organizar informações;
- imagens responsivas;
- estados de interação, como `:hover` e `:focus`;
- pelo menos uma media query;
- adaptação para computadores, tablets e celulares.

Não deverão existir textos cortados, elementos sobrepostos ou rolagem
horizontal indevida.

## Planejamento do JavaScript na Versão 1

Na primeira versão, o estudante deverá criar no `README.md` uma seção chamada
**Funcionalidades planejadas para a Versão 2**.

Deverão ser planejadas pelo menos duas funcionalidades. Para cada uma, deverá
ser informado:

- nome da funcionalidade;
- página em que será utilizada;
- elementos da página envolvidos;
- ação realizada pelo usuário;
- comportamento esperado;
- contribuição da funcionalidade para o portal.

Exemplo:

| Funcionalidade | Página | Ação do usuário | Comportamento esperado |
| --- | --- | --- | --- |
| Filtro de categorias | `conteudos.html` | Selecionar uma categoria | Mostrar apenas os conteúdos relacionados |
| Validação do formulário | `contato.html` | Enviar o formulário | Validar os campos e orientar o preenchimento |

O planejamento poderá ser alterado durante o desenvolvimento, desde que o
`README.md` seja atualizado.

## Requisitos de JavaScript da Versão 2

Na segunda versão, o portal deverá possuir **no mínimo duas funcionalidades
desenvolvidas com JavaScript**.

Algumas possibilidades são:

- menu responsivo;
- filtro de conteúdos;
- campo de pesquisa;
- validação de formulário;
- contador de caracteres;
- alternância entre tema claro e escuro;
- exibição e ocultação de informações;
- galeria de imagens;
- carrossel;
- modal com informações adicionais;
- atualização dinâmica de conteúdo;
- armazenamento de preferências com `localStorage`.

As funcionalidades deverão possuir uma finalidade coerente com o portal. Um
botão ou um `alert()` sem relação com a proposta não será considerado uma
funcionalidade completa.

O JavaScript deverá estar em arquivo externo e utilizar:

- seleção de elementos do HTML;
- eventos;
- funções;
- condições ou validações;
- manipulação de conteúdo, atributos ou classes.

## Conteúdo e experiência de navegação

Cada página deverá possuir conteúdo suficiente para justificar sua existência.
Não serão aceitas páginas vazias ou criadas apenas para atingir a quantidade
mínima.

Os textos poderão ser autorais ou baseados em fontes externas. Sempre que forem
utilizados textos, imagens, códigos, ícones ou outros recursos de terceiros, as
fontes deverão ser informadas no `README.md`.

Evite utilizar grandes blocos de `Lorem ipsum`.

## Organização sugerida

```text
nome-do-projeto/
├── index.html
├── conteudos.html
├── contato.html
├── assets/
│   ├── css/
│   │   └── global.css
│   ├── js/
│   │   └── script.js
│   └── images/
├── README.md
└── LICENSE
```

Os nomes dos arquivos deverão utilizar letras minúsculas, não possuir espaços
ou acentos e indicar claramente seus conteúdos.

## Documentação do projeto

O `README.md` do estudante deverá apresentar:

- nome do projeto;
- descrição do portal;
- justificativa do tema;
- objetivo;
- público-alvo;
- nome completo do estudante;
- mapa das páginas;
- descrição das páginas desenvolvidas;
- funcionalidades planejadas ou implementadas;
- tecnologias utilizadas;
- instruções para executar o projeto;
- link da aplicação publicada;
- capturas de tela;
- referências utilizadas.

## Entregas

### Entrega da Versão 1

A primeira entrega deverá conter:

- link do repositório individual no GitHub;
- páginas desenvolvidas com HTML;
- arquivos de estilização com CSS;
- mapa de páginas;
- wireframe ou protótipo;
- `README.md` completo;
- planejamento de pelo menos duas funcionalidades com JavaScript;
- link da Versão 1 publicada.

### Entrega da Versão 2

A segunda entrega deverá conter:

- o mesmo repositório utilizado na Versão 1;
- correções e melhorias realizadas;
- arquivos JavaScript organizados;
- pelo menos duas funcionalidades implementadas;
- `README.md` atualizado;
- link da versão final publicada;
- apresentação individual.

Todos os links deverão ser testados antes de cada entrega.

## Apresentação individual

Durante a apresentação, o estudante deverá:

1. explicar o tema e o objetivo do portal;
2. identificar o público-alvo;
3. apresentar a organização das páginas;
4. demonstrar a navegação e a responsividade;
5. demonstrar as funcionalidades desenvolvidas com JavaScript;
6. explicar partes do próprio código;
7. comentar as dificuldades e soluções encontradas;
8. apresentar a aplicação publicada.

## Restrições

O projeto deverá ser desenvolvido com:

- HTML;
- CSS;
- JavaScript.

Não será permitido utilizar templates prontos que entreguem a interface
completa, copiar integralmente projetos da internet ou reutilizar o projeto
desenvolvido em dupla como entrega individual.

O estudante deverá compreender todo o conteúdo e todo o código entregue.

## Uso de Inteligência Artificial

Ferramentas de Inteligência Artificial poderão ser utilizadas como apoio para:

- compreender mensagens de erro;
- revisar textos;
- pesquisar conceitos;
- esclarecer dúvidas;
- receber sugestões de melhoria.

O uso dessas ferramentas não substitui o desenvolvimento e a compreensão do
projeto. Durante a apresentação, o professor poderá solicitar:

- explicação de partes do código;
- alteração de uma funcionalidade;
- identificação de um elemento HTML ou de uma regra CSS;
- explicação do funcionamento do JavaScript.

Caso o estudante não consiga explicar ou modificar o próprio projeto, isso
poderá afetar sua avaliação.
